Deploy your Z relay

The relay is the one piece you host — a dumb pipe that shuttles encrypted messages between devices and stores nothing readable. This gets one running on Render's free tier and hands you a wss:// address to paste into the app. No domain, no credit card, about 10 minutes.

host Render free cost $0 domain not needed time ~10 min you already have the source zip

Before you start

Two free accounts — make them first and the rest is just clicking:

  • A GitHub account (Render deploys from here).
  • A Render account — choose “Sign in with GitHub”, which links them in one step.

The five steps

  1. 1

    Unzip the project

    Unzip z-messenger-src.zip (the source I sent you) somewhere on your computer, then open a terminal in that folder — the one containing render.yaml and the server/ folder.

  2. 2

    Put the code on GitHub

    Run the helper script — it creates a private GitHub repo and pushes the code for you:

    bash deploy/setup-relay.sh

    It installs nothing and only touches this folder. If it asks you to log in to GitHub, follow the browser prompt. When it finishes it prints your repo link and the next step.

    No gh installed? The script prints the exact manual git commands instead — or install the GitHub CLI first to keep it automatic.
  3. 3

    Deploy on Render

    In the Render dashboard:

    Click New → Blueprint → Connect your z-messenger repo → give it any name → Deploy Blueprint. Render reads render.yaml automatically and provisions a service called z-relay. Wait until it shows Live (~2 min).

    What Render shows A service named z-relay, runtime Docker, plan Free, health check /health — all pre-filled from the blueprint. You don't type any of it.
  4. 4

    Get your relay address

    At the top of the service page is its URL, like https://z-relay-a1b2.onrender.com. Confirm it's alive — open:

    https://z-relay-a1b2.onrender.com/health
    You should see {"ok":true, … ,"storage":"ram-only"} — that's your relay saying it's up and stores nothing on disk.
    ▸
    Your address for the app is that URL with wss:// instead of https://:
    wss://z-relay-a1b2.onrender.com  (the app also accepts the https:// form and converts it).
  5. 5

    Point the app at it

    Open Z on your phone/desktop. On the first screen (or later in Settings → Relay), paste your wss:// address and tap Test connection — you want the green ✓. Everyone you chat with points at the same address. That's it — you're live.

About the free tier

✓
WebSockets work on Render free, and message traffic counts as activity — so while you're actively chatting the relay stays awake. You get 750 instance-hours/month, plenty for a personal relay.
!
After 15 minutes with no traffic a free service sleeps and takes ~1 minute to wake on the next connection. Messages aren't lost — the sender's app holds them and resends when the relay wakes. For an always-on relay, change plan: free to plan: starter in render.yaml (or in the dashboard) and redeploy — a few dollars a month, no sleep.

When you outgrow one relay

You don't need this yet — start with one. When you want high availability or more throughput, the repo ships a ready multi-instance setup (several relays behind a load balancer sharing a RAM-only Redis, still zero-knowledge):

cd server docker compose -f docker-compose.ha.yml up --build --scale relay=3

Details in docs/SELF_HOSTING.md. Note relays don't federate yet: both people in a chat must use the same relay address.

If something's off

The app shows “offline” / a red dot.

Check the address starts with wss:// and matches the Render URL exactly. Open the /health link to confirm the relay is awake.

First message after a while is slow.

That's the free tier waking up (~1 min). Upgrade to Starter to remove it.

Render says the build failed.

Make sure you picked Blueprint (not “Web Service”) so it reads render.yaml. Re-run from New → Blueprint and select the repo again.

“Test connection” fails right after deploy.

Give Render a minute to finish; refresh the service page until it says Live, then retry.
